PlayDock — DLsite 양방향 검색 실험판 (2026-11-21)

폴더에 두 개의 서로 독립적인 Windows 실행파일이 있습니다.

1) PlayDock-Name-to-Code.exe
   게임 이름을 입력해 DLsite 품번(RJ/VJ/BJ/EJ)을 검색합니다.
   [압축파일 선택 (여러 개 가능)] 또는 [폴더 내 압축파일 선택]을 누르세요.
   게임명 입력란에 작품 이름을 직접 적어도 됩니다.
   선택한 파일은 실제로 열지 않고 파일명에서 게임 이름을 추출합니다.
   파일명에 품번이 이미 있으면 검색하지 않고 DLsite 공식 페이지로 직접 확인합니다.
   품번이 없으면 한국어 제목을 정제하고, 병기된 영어 제목도 독립 검색합니다.
   이름 검색은 따옴표/특정 사이트 한정 없이 일반 웹 검색 HTML도 사용합니다.
   검색 페이지의 제목에 품번이 함께 있다면 후보로 수집하고 DLsite에서 다시 확인합니다.
   검색 사이트 접근 차단과 정답 없음은 구분합니다.
   [브라우저에서 직접 찾기]는 검색어를 따옴표/도메인 한정 없이 Google에서 열며,
   파일명에 품번이 있는 경우에는 DLsite 공식 품번 페이지로 이동합니다.
   검색 후보만 나온 경우는 공식 확인으로 처리하지 않습니다.

2) PlayDock-Code-to-Name.exe
   RJ12345678처럼 품번을 입력해 DLsite 공식 이름을 확인합니다.
   [압축파일 선택 (여러 개 가능)]으로 ZIP/7z/RAR을 고르거나,
   [폴더 내 압축파일 선택]을 사용하면 파일명에 포함된 품번을 자동 추출합니다.
   품번만 직접 입력하는 기존 방식도 계속 지원합니다.
   파일명에 품번이 없거나 여러 개면 자동 선택하지 않고 경고합니다.
   공식 작품 HTML을 직접 확인하며, 조회 실패를 미등록으로 단정하지 않습니다.

공통 기능
- API 키 불필요. JSON API 또는 유료 검색 API 호출 없음.
- 공개 웹 검색 결과(HTML 및 Bing RSS)를 읽음. 사용자 압축파일을 열거나 압축 해제하지 않음.
- 선택한 로컬 파일의 전체 경로를 웹으로 보내지 않고 이름만 검색함.
- 여러 압축파일 동시 선택, 폴더 직하위 압축파일 수집, 선택 목록에서 제거,
  직접 입력과 파일 선택 혼합 가능. 최대 1,000개 일괄 검색.
- 검색 진행률, 중단, 결과 JSON/CSV 저장. 결과에는 선택했던 원래 파일명과
  입력 방식(파일 선택 / 직접 입력)을 함께 남깁니다.
- 후보를 더블클릭하면 공식 상품 웹페이지를 브라우저로 엽니다.
- 사이트가 자동 조회를 차단하면 [브라우저에서 직접 찾기] 버튼으로
  기본 브라우저의 일반 Google 검색 또는 공식 DLsite 작품 페이지를 열 수 있습니다.
- [공식 제목 일치], [공식 품번 확인], [검색 링크 후보]를 엄격히 구분합니다.
- 게임 유형/버전/실제 압축파일 내용은 검증하지 않습니다.
- 개인 입력 내용과 검색 결과는 GitHub에 업로드하지 않습니다.

주의
- DLsite 검색 HTML은 JavaScript 렌더링 또는 접근제한으로 작품 링크가
  보이지 않을 수 있습니다. CAPTCHA나 성인인증 등을 우회하지 않습니다.
- 검색 오류나 후보 없음은 '상품이 없다'는 뜻이 아닙니다.
- 검색 결과에 동명이작, 다른 언어, 번역판이 섞이면 후보를 수동 검토하세요.
- 네트워크 접속이 필요합니다. 검색 사이트 정책·구조 변경에 영향을 받습니다.
- 창이 뜨지 않으면 EXE를 직접 실행하고 Windows SmartScreen 메시지를 확인하세요.
- 실험 버전이며 PlayDock 메인 앱/DB를 수정하지 않습니다.

최종 정확도는 실제 사용자 데이터 검증 전까지 미측정입니다.

API 키 없는 자동 메타검색 실험판 (2026-11-21 추가)
- 이름→품번 모드에서 파일명에 품번이 없으면 DDGS 라이브러리로 검색을 자동 실행합니다.
- DuckDuckGo/Brave/Bing 결과의 제목·URL·검색 요약에서 DLsite 코드 후보를 수집합니다.
- 결과를 사람이 선택하거나 크롬에서 직접 복사할 필요가 없습니다.
- 공식 DLsite 작품 HTML이 보이면 후보 코드와 공식 작품명을 다시 검증합니다.
- 공식 작품명(일본어)과 번역명(한국어)이 다르면 일치 여부가 확인되지 않아 검토 후보로 분류합니다.
- 검색엔진이 차단하거나 코드를 반환하지 않으면 검색 실패로 기록합니다. 강제 우회는 하지 않습니다.
- Google HTML 보조 검색은 결과 추출이 불안정합니다. DDGS와 Bing RSS가 주 검색 경로입니다.
- 브라우저에서 직접 찾기는 자동 검색이 실패했을 때만 선택적으로 사용할 수 있는 보조 기능입니다.
- 이전 129개 실사용 결과는 이름 검색 신규 품번 0/40입니다. 이번 판은 다시 측정해야 합니다.

다국어 검색 및 Bing RSS 개선판 (2026-11-21)
- 파일명에 품번이 있으면 기존처럼 그 품번의 DLsite 공식 페이지를 직접 확인합니다.
- 품번이 없으면 한국어·영어·일본어로 실제 표기된 별칭을 각각 독립 검색합니다.
  예: '번역 게임 제목 (English Title).zip'이면 영문 제목, 한국어 제목, 전체 제목을 구분합니다.
- 한국어를 일본어로 임의 번역하지 않습니다. 웹 검색 결과에 '원제: 日本語タイトル'처럼
  원제가 명시된 경우에만 일본어 제목을 추가 수집하고 DLsite에서 다시 검색합니다.
- DDGS의 DuckDuckGo/Brave/Bing 엔진은 독립적으로 시도합니다.
- API 키 없는 Bing RSS(https://www.bing.com/search?format=rss&q=...)를 추가하여
  검색 결과의 제목·링크·요약문을 자동 수집합니다. 브라우저에서 선택할 필요가 없습니다.
- DLsite 공식 제목이 일본어이고 파일명이 한국어인 경우, 웹에서 원제 연결이 확인돼도
  동일 작품 확정을 강행하지 않고 검토 후보로 남깁니다.
- 합본 게임(+ 기호)은 각각의 작품명을 분리해 검색하며 단일 작품으로 합치지 않습니다.
- 검색 결과가 없거나 공식 페이지가 차단되면 없다고 확정하지 않습니다.
- GitHub Windows 자동 테스트 97건 통과. 공개 일반 검색어로 DDGS 9건,
  Bing RSS 10건을 수집했지만 DLsite 공식 HTML은 GitHub 환경에서 접근 오류가 있었습니다.
- 사용자 실제 40개 무품번 파일의 신규 품번 발견률은 이 버전으로 재검증하기 전까지 미측정.


DLsite 우선 검색 전환 (2026-11-21)
- 품번이 없는 파일의 검색 순서: 1) DLsite 공식 카탈로그 → 2) Bing RSS → 3) DDGS.
- DLsite에서 게임 이름과 관련된 품번 후보가 나오면 불필요한 Bing RSS·DDGS 검색을 생략합니다.
- 관련 후보가 없거나 공식 검색이 오류이면 Bing RSS로 이어서 검색합니다.
- Bing RSS에서도 못 찾으면 DDGS(DuckDuckGo / Brave / Bing)를 시도합니다.
- Bing RSS 또는 DDGS가 명시적 일본어 원제를 찾았지만 품번을 찾지 못했다면,
  해당 원제로 DLsite를 다시 검색합니다. 검색어와 카테고리 중복 조회는 방지합니다.
- 파일명에 RJ/VJ/BJ/EJ가 있으면 검색하지 않고 그 품번의 공식 작품 정보를 직접 확인합니다.
- 외부 검색에서 찾은 품번은 공식 작품 페이지를 확인한 후에도 원제와 번역명
  동일성은 자동 확정하지 않습니다. 관련 후보가 없어도 미등록 판정은 하지 않습니다.
- Google HTML은 자동화 환경에서 검색 결과를 수집하지 못하는 경우가 있으므로
  기존 마지막 보조 검색에만 남겨 두었습니다.
- 자동 검색 결과 정확도는 사용자 실파일 목록으로 재측정해야 합니다.


v7 후보 판독·진단 개선 (2026-11-21)
- DLsite 일본어 공식 제목에 가나(히라가나/가타카나)가 있으면 영어 로마자
  작품명과 발음의 유사성을 보조 비교합니다. 예: BUZAMA 3 ↔ ブザマ...3.
- 일본어 한자 독음을 임의 추측하거나 한국어를 일본어로 자동번역하지 않습니다.
- 시리즈 번호가 다르면 후보를 제외하고, 발음이 비슷해도 자동 확정하지 않습니다.
- 결과 JSON의 각 항목에 catalog_review를 추가하여 DLsite에서 수집한
  작품번호·제목·일치점수·탈락 사유를 최대 30개 저장합니다.
  검색기 오른쪽/아래 '상세 근거'에도 동일 정보를 표시합니다.
- 후보 캐시는 %LOCALAPPDATA%\PlayDock\identity_lookup_candidates.json에
  사용자 로컬로만 저장되며 설치본/공개 GitHub에는 포함되지 않습니다.
  과거에 찾은 품번이 현재 검색에서 사라져도 '과거 후보·재확인 필요'로 표시합니다.
  과거 후보는 현재 확인으로 간주하지 않으며 자동 확인 수치에도 포함하지 않습니다.
- 기존 v4/v5/v6 JSON을 가지고 있으면 '이전 결과 JSON 가져오기' 버튼으로
  한꺼번에 불러올 수 있습니다. 이미 저장한 과거 후보를 현재 검색에서
  다시 못 찾아도 수동 검토 후보로 보존할 수 있습니다.
- 로컬 이력은 자동 갱신되지 않는 별도 캐시이며, 삭제하려면 위 JSON 파일을
  사용자 본인이 삭제할 수 있습니다. 보존기간은 최대 180일, 게임 제목 최대 1200개.
- 검색 순서는 기존 v6 그대로 DLsite → Bing RSS → DDGS입니다.
- 실제 사용자 40개 무품번 검색 성공률은 새 실행 결과 JSON으로 재검증해야 합니다.
