# PlayDock 독립 게임 정체 판독기 v0.8 — 정확도 우선 구현 기록 (2026-11-19)

## 배경과 비교 기준
- 사용자의 개인 v0.7 검사 JSON은 129개 항목이고, 공식 카탈로그 발견 81개, 웹 후보 3개, 복수 후보 2개, 최종 일치 확인 0개였다.
- 검색시간보다 **잘못된 공식 출처·작품번호·게임 관계 판정을 줄이는 일**을 우선했다.
- 개인 JSON, 게임 원본, 게임 목록, 내부 경로, API 키, 개발자의 로컬 DB는 공개 저장소에 올리지 않았다.
- v0.7 원본은 정확도의 정답표가 아니다. v0.8의 실사용 정확도 향상률은 아직 측정하지 않았다.

## 실제 수정
1. `storefront_candidate.py` — itch.io 하위 `/comments`, `/devlog` 및 Steam 상품 페이지가 아닌 하위 경로를 게임 개별 상품 홈이라고 오인하지 않는다. HTTPS·호스트·표준 포트·상품 경로를 확인한다. 검색 근거 자체는 버리지 않지만 공식 상품 홈 후보로 승격하지 않는다.
2. `enhanced_search.py` — 웹 제목/URL의 RJ/BJ/VJ/EJ 코드를 공식 조회했더라도 **검색 대상 제목과 공식 작품명이 정확히 일치**하거나 **같은 짧은 검색 제목에서 검색 대상과 공식 작품명이 함께 명시적으로 연결**되어야 공식 후보로 승격한다. 다른 게임의 코드, 다수 코드, 공식 조회 실패는 `web_code_hints`에만 남기며 `official_code_verified=False`를 유지한다.
3. `identity_matcher.py` + `identity_verifier.py` — 후보별 그룹에서 출처가 확인된 공식 제품번호만 후보의 `official_ids`에 넣는다. 전체 카탈로그 목록에 있는 DLsite 코드를 이름이 다른 Steam 후보의 ID로 복사하지 않는다. 플랫폼 간 공식 링크가 없으면 별개의 후보로 유지한다.
4. `verification_report.py` + `identity_verifier.py` + `scripts/game_identity_tester.py` — `local_name_support` 필드와 GUI 표시로 외부 게임 제목에 대해 **압축파일명·내부 EXE/폴더명·파일명에 적힌 공식 코드 주장**의 일치를 따로 보여준다. 파일명 주장에는 "진위 미검증"을 명시하며, 이것으로 `matched`를 늘리지 않는다.

## 안전 정책
- 압축파일명 + 내부 파일·폴더의 이름/구조 + 선택적 README 제한 필드를 **전부 수집한 뒤** 검색하는 순서를 유지.
- JSON·INI·EXE·엔진 설정의 본문은 기본 검사에서 읽지 않음. README 제한 읽기와 암호화 파일의 파일명 전용 검색 유지.
- 본편·DLC·번역 패치·합본, 공식 플랫폼 불일치, 다국어 제목 관계는 독립 공식 연결이 없으면 강제로 병합하지 않음.
- UI와 기능 모듈 분리, 개인 DB/원본 게임 파일 불변, PR #2 Draft 유지 및 `main` 미병합.
- 검증 근거가 부족한 경우 **후보 미확인**으로 처리하는 것은 오류가 아니라 의도적인 안전 조치.

## 자동 회귀 검증
- 합성 압축파일과 모의 웹 검색으로 댓글/개발일지 URL 승격 방지, 무관한 코드 후보 거부, 후보별 ID 분리, 제목/내부 파일명 근거 표시만 수행하고 확정하지 않는 조건 등을 검증.
- `python -m pytest -q` 전체 GitHub Actions 612개 통과: https://github.com/sanato-nb/PlayDock/actions/runs/44365981122
- 실사용 129개 압축파일의 v0.8 재검사는 완료되지 않았으며 오탐률·정확도 개선 수치는 아직 확인할 수 없다.
