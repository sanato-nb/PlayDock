## 2. 반드시 지켜야 할 검색 순서

**압축파일 이름 + 압축파일 내부에서 확보 가능한 근거를 모두 모은 후 하나의 검색 계획으로 통합 → 인터넷 검색 → 최종 6단계 검증.**

파일명부터 먼저 검색하거나 내부만 우선 검색하는 설계는 하지 마. 비암호화 ZIP/7z/RAR은 목록·제한된 메타데이터 수집. 암호화/암호 상태 불명 파일은 내부를 읽지 말고 이름만 검색. 원본 압축은 수정/전체 해제/실행하지 마.

**작품 카탈로그 발견과 내 압축파일이 그 게임인지 확인하는 것은 완전히 다른 판단**으로 유지해. 패치/DLC/번역판/합본, 동일 게임의 다국어 이름·다른 플랫폼 ID를 정확히 구분해야 하고 근거 없는 자동 등록/병합은 금지.

## 3. 검증된 현재 상태 (v0.5)

- 실험 브랜치의 v0.5-test Windows GUI에서 사용자 압축파일 **129개** 검증.
- 동일 128개에서 v0.4 1068.725초 → v0.5 314.084초(**70.61% 단축**, 검색 생략 영향 포함).
- v0.5 총 318.092초, 카탈로그 상태 `official_game_found=79`, `web_candidate=2`, `multiple_candidates=1`, `lookup_error=30`, `not_found=17`.
- 검색 `requests=162`, 캐시 재사용 5, 장애로 생략 20, 오류 39; 13개 파일에서 생략 발생.
- 최종 `likely_candidate=4`, `matched=0`. 실제 식별 정확도는 독립 정답표가 없어 미측정. 카탈로그 후보가 잡힌 것은 로컬 파일 진위 확인이 아님.
- 마지막 기능 기준 전체 Python 테스트 592개 통과, Windows EXE 자체 진단 통과. **현재 브랜치 상태에서 다시 확인할 것**.
- 개인 게임 129개의 JSON/상세 감사 보고서는 공개 GitHub에 저장하지 않았어. 필요하면 내가 이 채팅에 다시 첨부할게. 이 자료가 없어도 저장소의 합성 테스트와 소스 검토로 작업을 시작해.

## 4. v0.6에서 실제 수행할 작업

**P0: 웹 검색 결과에 작품번호나 개별 상품 페이지가 보여도 'not_found'로 버리는 버그 수정.** URL/제목의 후보 ID를 추출한 뒤 출처·신뢰도를 기록하고 공식 등록 페이지를 확인해. 검색 결과가 제3자 카탈로그뿐이라면 공식 확인으로 승격하지 말고 `미확인 외부 후보`로 보존해. 시리즈물 2/3 같은 숫자 차이도 유지해.

**P0: 검색 쿨다운으로 넘어간 파일을 단순 미발견과 구분하고 재검사 가능하게 수정.** 건너뛴 파일의 이유·시점·재시도 상태를 명시하고 검색 서비스 복구 후 가능한 범위에서 선택적 재시도를 지원해. 무제한 웹 요청/지연은 금지.

**P1: 다국어·다른 플랫폼 후보를 안전하게 통합.** 동일 공식 작품번호, 원본 페이지 교차 링크, 명시적 다국어 병기처럼 검증되는 경우만 병합. 서로 다른 공식 ID와 DLC/원작·패치 상품은 무분별하게 합치지 마.

**P1: 1~6단계 소요시간을 개별 계측.** 파일명 분석/암호 판독/목록 스캔/설정 메타/외부 검색/최종 검증 시간(ms)과 전체 벽시계를 JSON에 기록해. 파일명·내부 근거를 모두 모은 뒤 검색하는 순서는 유지해.

**P1: 공통 런타임 경로의 반복 근거를 UI에서는 요약하되 기존 원본 내부 근거를 제거하거나 손실시키지 않기.**

## 5. 실제 산출물과 검증 기준

- 테스트는 개인 파일 경로·개인 게임명 복사 대신 **합성 ZIP 및 모의 웹 응답**으로 재현. 사용자 JSON은 반드시 비공개 분석.
- 기존 `src/playdock/` 및 DB/라이브러리/이미지/키는 변경하지 않음. UI는 GUI만, 분석·검색 로직은 독립 모듈로 유지.
- `python -m pytest -q` 전체 검사, 필요 시 Windows GitHub Actions **수동 실행**으로 EXE `--self-test`. 실패하면 실패/미검증이라고 정확히 설명.
- 변경 사항을 **기존 실험 브랜치**에 한국어 커밋으로 반영, Draft PR #2 유지. `main`은 건드리지 않음.
- 파일/폴더 트리를 보여줄 때 각 경로 옆에 **무슨 역할인지 한글로 작성**.
- 완료 시 **변경 파일별 기능, 커밋 SHA, CI 결과, 확인한 버그, 실제로 개선된 점과 남은 문제**를 보고.
- 시간이 제한되더라도 실제 수정·테스트·커밋 가능한 것부터 실행해. 계획서만 쓰고 끝내지 마.
