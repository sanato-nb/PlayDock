# PlayDock 독립 게임 정체 판독기 v0.6 — 실제 구현 기록 (2026-11-19)

> 대상은 **실험 브랜치** \`experiment-dlsite-game-detector-20261117\`의 독립 프로그램이다.
> PR #2는 Draft, \`main\` 병합하지 않는다. 실사용 개인 JSON·압축 경로·API 키는 이 저장소에 포함하지 않는다.

## 검색·판별 변경
- **검색 순서 불변:** 압축파일명 및 비암호화 내부 목록/작은 메타데이터를 **모두 수집한 후** 검색 후보를 통합·정렬하고 인터넷 조회, 마지막에 6단계 비교. 암호 상태가 불명이거나 암호화된 파일은 이름으로만 검색한다.
- **검색 결과 작품번호 복구:** 웹 검색 제목/HTTPS URL의 RJ/BJ/VJ/EJ 코드를 최대 두 개까지 후보로 식별한 뒤 DLsite 원본 작품 코드를 재조회한다. 공식 코드/게임 형식이 검증된 경우라도 로컬 압축파일 일치는 자동 확정하지 않는다. 여러 번호·조회 실패는 미확인 후보로만 보존한다.
- **조회 결과 구분:** \`search_state\`는 \`network_error\`, \`cooldown_skipped\`, \`not_found\`, \`unverified_evidence\`를 구별한다. 웹 작품번호는 \`web_code_hints\`와 공식 재조회 플래그로 표시하여 검색 스니펫만으로 공식 코드로 승격하지 않는다.
- **오류 재검사:** GUI '검색 실패 항목 재검사'를 누르면 이전에 실패·생략·미확인 코드가 있는 파일만 재조회한다. 파일 크기와 수정시각이 같고 이전 목록이 남아 있으면 내부 파일 목록·메타데이터를 재사용하여 중복 읽기를 줄인다. 원본이 변경되면 다시 안전하게 전체 검사한다. 비암호화 검사가 재검사 사이 변경되지 않았음을 **암호학적으로 보증하는 방식은 아니므로** 사용자 검토를 계속 요구한다.
- **언어·플랫폼:** 공식에 명시된 병기 제목, 동일 공식 등록번호, 같은 플랫폼 상품번호만 통합한다. DLsite와 Steam을 함께 공식 확인한 단일 결정 \`dlsite+steam\`이 있을 때만 별도의 교차 플랫폼 후보 그룹 병합을 허용한다. 다른 DLsite 코드 및 패치/본편은 무조건 같은 상품으로 합치지 않는다.

## 시간 측정
\`stage_timings_ms\`에 다음을 기록한다.
- \`archive_name_parse_ms\`: 압축파일명 해석
- \`encryption_probe_ms\`: 암호화 상태 판별
- \`index_scan_ms\`: 압축 내부 목록
- \`metadata_read_ms\`: 작은 메타데이터 확인
- \`search_plan_ms\`: 근거 통합·검색어 선정
- \`search_ms\`: 일반 웹·공식 카탈로그 조회
- \`verification_ms\`: 최종 교차검증
- \`total_ms\`: GUI 파일별 전체 벽시계 처리시간

캐시·네트워크 상태와 조회 실패 비중이 속도를 크게 바꾸므로 이전 129개 실사용 검사와 직접 성능 비교는 아직 수행하지 않았다.
