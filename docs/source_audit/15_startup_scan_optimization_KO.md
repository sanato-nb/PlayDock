# 5-A 초기 게임 목록 스캔 최적화

기준 54dd052076afa2cc2b288f2e3aa43c55a282c03f. 4-C 집중 및 전체 테스트 단계 성공 확인; 빌드 완료 여부 별도 확인. https://github.com/sanato-nb/PlayDock/actions/runs/45357769603

기존 Library.scan()은 설치 폴더의 게임 여부 확인에 executable_candidates()를 호출해 전체 후보 탐색, 파일 크기 조회, 점수 산정 및 정렬을 수행했다. 실제 목록 등록에는 후보 존재 여부만 필요하다.
공통 _iter_executable_paths()에서 기존 제외 규칙·최대 깊이·확장자 검사를 유지한다. has_executable_candidate()는 첫 후보에서 반환, executable_candidates()는 기존 점수/정렬 및 전체 후보 처리 유지. 실행 승인 및 실제 실행파일 선택 로직 불변. 설정된 경로가 있는 경우 root/archive_root 속성의 불필요한 기본 폴더 조회를 제거한다.
검증: 동일 폴더 결과, 제외 파일과 폴더, 깊이 한계, 기존 순위, 실제 라이브러리 스캔 동등성, 41개 합성 EXE의 디렉터리 방문 41→1 및 크기 stat 41→0, 설정 경로 폴백, 전체 회귀 및 EXE 빌드. 후보가 없는 폴더는 기존과 동일한 탐색 범위. 합성 실측 시간은 로그에만 기록, 실제 사용자 환경 성능 보장 아님. 사용자 데이터/DB/압축/설치된 게임 파일 변경 없음.
