# PlayDock 설정 메뉴 · SQLite DB 상태 안내

## 상단 구성

- 기존 라이브러리/내 모음집 탐색은 유지합니다.
- 오른쪽 상단에는 '새로고침'과 '설정' 버튼 두 개만 표시합니다.
- 설정 메뉴: 이름 설정(여러 게임), 폴더 설정, 데이터 관리, 라이브러리 속성, AI 설정, DB 상태 확인.
- 목록 우클릭의 '이 게임 이름 설정'은 기존대로 해당 게임 하나만 편집합니다.

## DB 상태 확인

설정 → DB 상태 확인을 누르면 실제 로컬 SQLite 파일을 읽기 전용으로 검사해 다음 항목을 표시합니다.

1. PlayDock 본체: 저장 폴더/data/playdock.db (SQLite user_version 2)
   - 기존 DLsite 작품 정보 works
   - 라이브러리 연결 기록 library_links
   - 정체 판독기에서 가져온 DLsite+Steam 공식 작품정보 official_works
   - 사이트별 공식 작품정보 건수, SQLite 빠른 무결성 검사 결과
2. 정체 판독기 원본: %LOCALAPPDATA%/PlayDock/official_works.sqlite3
   - 품번, 공식 작품명, 작품 종류·분류, URL, 확인 일시
   - 사이트별 건수, SQLite 빠른 무결성 검사 결과
3. 현재 라이브러리에 표시된 게임 수 (DB 행 개수와 별개)

원본 DB가 없거나 손상된 경우 파일 없음/읽기 실패로 표시하며 DB를 새로 만들지 않습니다.
이름 변경·게임 파일 변경·데이터베이스 업데이트도 수행하지 않습니다.

## 현재 구조의 나머지 데이터

- settings.json: 프로그램 및 폴더 설정
- collections.json: 사용자 모음집
- 게임별 메타데이터 JSON: 사용자 수정 제목, 게임 설정
- 이미지 캐시 파일: 아이콘/배너
- playdock.db: DLsite 작품 상세, 연결 기록, 가져온 공식 작품정보
- official_works.sqlite3: 스캐너가 수집한 공식 작품정보 원본

PlayDock 시작/새로고침은 스캐너 DB를 본체 공식정보 테이블로 가져옵니다.
두 DB의 작품 건수가 달라도 즉시 오류를 의미하지 않습니다. 마지막 가져오기 이후
새 작품이 생겼거나, 기존에 가져온 작품이 원본 DB에서 사라진 경우가 있을 수 있습니다.
앱 백업은 playdock.db를 포함하지만 독립 스캐너 DB는 별도이므로 백업 범위에 주의하세요.
