# PlayDock v0.8.4 이후 계층 분리 진행 기록

## 이번 변경

- 이미지 검색·다운로드·식별 QThread 3종을 `services/artwork_workers.py`로 이전. UI는 신호 및 화면 갱신만 담당.
- DLsite 작품 조회 작업자를 `services/work_lookup_worker.py`로 이전. 결과 확인은 기존 UI에서 사용자 동의 후 실행.
- AI 제공자·모델·자격 증명 저장은 `services/settings_service.py`에서 처리하며, 기존 Windows keyring과 settings.json 형식을 그대로 사용.
- 캐시 이미지 검사·휴지통 이동과 데이터 인벤토리·ZIP 백업·검증·복원을 실제 `services/` 구현으로 이전.
- 모음집·캐시·백업 UI 이벤트는 `controllers/data_manager.py`의 동작 객체로 연결.
- `cache_management.py`와 `data_management.py`는 기존 테스트·플러그인 import를 위한 호환 경로 유지.
- EXE 생성·설치기와 Windows 자동 빌드는 실행하거나 활성화하지 않음. 데이터 파일 이동·정리·초기화 없음.

## 변경 대상 소스 구조

```text
PlayDock/                                        # 프로젝트 최상위 폴더
├── app.py                                      # MainWindow에서 데이터 관리 Controller 연결
├── src/                                        # Python 소스 폴더
│   └── playdock/                               # PlayDock 패키지
│       ├── cache_management.py                 # 이전 캐시 함수 import 호환
│       ├── data_management.py                  # 이전 백업·데이터 함수 import 호환
│       ├── controllers/                        # 사용자 명령을 실제 기능으로 전달
│       │   ├── data_manager.py                 # 모음집·이미지 캐시·백업·복원 동작 조정
│       │   └── metadata.py                     # DLsite 스레드 요청과 결과 적용 조정
│       ├── services/                           # Qt 화면에 의존하지 않는 업무 및 백그라운드 처리
│       │   ├── artwork_workers.py              # 이미지 검색·다운로드·작품 식별 작업자
│       │   ├── work_lookup_worker.py           # DLsite 작품 조회 작업자
│       │   ├── settings_service.py             # AI 모델·API 키·폴더 설정
│       │   ├── cache_service.py                # 이미지 캐시 조회 및 휴지통 이동
│       │   └── data_service.py                 # 데이터 조사·ZIP 백업·검증·복원
│       └── ui/                                 # 화면 표시 및 사용자 확인
│           ├── artwork_dialog.py               # 이미지 검색 결과·자르기 UI
│           ├── work_info_dialog.py             # DLsite 미리보기 및 기존 작업자 import 호환
│           └── dialogs/                        # 공통 설정·정보 대화상자
│               └── library.py                  # AI 설정·캐시·모음집·백업의 입력 화면
├── tests/                                      # pytest 회귀 테스트
│   ├── test_worker_settings_separation_v085.py # 이미지·DLsite 스레드 및 AI 설정 분리 검사
│   └── test_data_controller_separation_v085.py # 캐시·백업·모음집 분리 및 데이터 보존 검사
└── .github/                                    # GitHub Actions 설정
    └── workflows/                              # 자동 검사 및 수동 EXE 빌드 워크플로
        ├── build-windows-exe.yml               # 수동 실행만 가능한 기존 Windows EXE 빌드
        └── python-tests.yml                    # Linux Python 테스트만 자동 실행
```

## 남은 점검 사항

- 이미지 선택·자르기 결과 적용과 일부 검색 상태 로직은 UI에 있으므로 추가적인 경계 점검이 필요함.
- 현재 변경은 압축 해제, 게임 설치·실행, 작품 SQLite 구조를 수정하지 않음.
- Linux 자동 테스트 성공은 실제 Windows Qt 창 클릭·Windows keyring·RAR/7z 설치 동작 검증을 의미하지 않음.
- Windows GUI/설치기 테스트는 별도 Windows 환경에서 실시해야 함.
