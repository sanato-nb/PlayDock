# PlayDock · 게임 정보 수집(DB 채우기)

## 사용 흐름
1. 라이브러리의 **게임 정보 수집**을 실행합니다. 게임 정체 판독 버튼보다 왼쪽에 있습니다.
2. 전체 게임의 파일명·명시적 품번을 분석해 DLsite → Steam 공식정보를 확인합니다.
3. 공식 작품명·원본 분류·제작사(제공되는 경우)·언어별 제목·태그·공식 페이지·이미지 후보 URL을 통합 `works` DB에 저장합니다.
4. 진행률과 기존 DB 재사용/신규 수집/미확인/오류 건수를 확인하고 중단할 수 있습니다.
5. 이어서 **게임 정체 판독**으로 특정 게임을 확인하고 배너/아이콘을 체크한 경우에만 적용합니다.
6. **게임 이름 설정**은 먼저 PlayDock 공식 작품 DB를 사용하고, 저장된 정보가 없는 DLsite 작품만 기존 조회를 시도합니다.

## 안전 및 사용 원칙
- 정보 수집은 **DB만 갱신**하며 압축파일·설치 폴더·표시 제목·배너·아이콘 PNG를 바꾸지 않습니다.
- 품번이 없는 게임은 건너뛰고 미확인 목록에 기록합니다. 비게임으로 단정하지 않습니다.
- 이미 확인된 (store, code)는 다시 요청하지 않되, 누락된 이미지 URL·언어별 제목은 원본 공식 사이트에서 보강할 수 있습니다.
- 같은 품번이 여러 파일에 있더라도 작품 정보는 DB에서 한 번만 보관합니다.
- 복수 품번으로 정체가 불명확하면 작품정보만 저장하고 게임을 억지로 연결하지 않습니다.
- 유료 API·이미지 생성·제목만으로 추측 검색·압축파일 내부 읽기는 사용하지 않습니다.
- 웹사이트 차단/네트워크 실패는 미확인으로 보고하고 기존 DB 데이터는 보존합니다.
- `인터넷 이미지 검색·편집` UI 버튼과 실행 경로를 제거했습니다. 수동 `이미지 직접 지정` 메뉴는 유지합니다.

## 구조
- `data/playdock.db`: `works`, `library_links`만 사용
- `services/catalog_collection_service.py`: DB 먼저 조회, 미확인 품번만 공식 조회
- `services/catalog_collection_worker.py`: 백그라운드 실행/중단/진행 신호
- `controllers/catalog_collection.py`: UI-서비스 연결
- `ui/dialogs/catalog_collection.py`: 진행률·실패 목록
- `services/title_workers.py`: DB 기반 공식 제목 우선
- 독립 정체 판독기는 계속 테스트 도구로 유지하고 PlayDock 본체와 같은 분석 엔진을 재사용합니다.
